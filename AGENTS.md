# AGENTS.md

## About

`agentguard` owns shared helpers and PATH-visible `agent-hook-*`
entry points. Hooks are agent-agnostic (Claude Code, Codex, Gemini
CLI, Grok, Muse, OpenCode, or another host that follows the same
protocol). AgentGuard never mutates an agent's configuration.

## Layout

- `bin/agent-hook-*` are thin host-facing entry points: parse payload,
  call library policy, exit with the status the host expects. Every
  tracked `bin/*` needs `man/man1/<name>.1` (`test/suites/manpage-test`).
- `lib/agentguard/` owns reusable policy: `hook-helpers.sh` is the
  hook-runtime API, `agentguard.sh` the detection API for non-hook
  callers, `detect.sh` internal. Consumers use
  `bin/agentguard-classify-command`, never private `_hook_*` helpers.
- `share/agentguard/integrations/` holds policy-free native fragments
  (event names, matchers, timeouts, identity, hook commands), each with
  a `README.md`. Change a fragment and `integration-assets-test` together.
- Secure launcher and resolver text is generated from
  `support/secure-launcher.sh.template` and
  `support/script-resolver.sh.template` into the launchers listed in
  `support/launcher-bootstrap.manifest`. After template or manifest
  edits, run `support/sync-hook-bootstrap`; the test runner's `--check`
  rejects stale copies.
- README is user-facing; contracts live in `docs/telemetry.md` and
  `docs/watch-protocol.md`. Don't add plan or spec scratch under `docs/`.

## Invariants

- Direct executable invocation through the privileged shebang is the
  supported security boundary. `HOME` and `PATH` never select the
  Bash interpreter. Explicit `bash script-path` is outside that
  boundary. See README for the loader-environment contract, whose
  wording `manpage-test` pins.
- Integration assets exclude permissions, models, MCP servers, UI
  settings, and machine policy.
- Muse gets the Codex-style `hookSpecificOutput.additionalContext`
  shape with no legacy `context` field and no `suppressOutput`.

## Testing

- Local: `test/agentguard-test` ShellChecks listed files, runs
  `support/sync-hook-bootstrap --check`, then every `test/suites/*-test`
  (`AGENTGUARD_TEST_JOBS` workers, default 4).
- CI shell job, full matrix, profiles `base,jq,python`:
  `AGENTGUARD_SKIP_SHELLCHECK=1 test/agentguard-test`.
- CI OpenCode job, once per pinned version (`opencode-ai@1.18.13`,
  `@opencode/cli@2.0.22`): `npm install --prefix "$p" --no-save
  --package-lock=false <package>@<version>`, then
  `PATH="$p/node_modules/.bin:$PATH" test/suites/opencode-agentguard-test`.
  Without `node`, that suite prints SKIP locally.

## Test isolation

- `test/helpers.sh` points `AGENTGUARD_TELEMETRY_DIR` at a temp dir;
  `_mock_home` sets a temp `HOME` and `GIT_CONFIG_GLOBAL`. Hive Memory
  suites use a logging `hm` stub and unset `XDG_CONFIG_HOME`. Never run
  hooks against a real `hm` store or the real audit log.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local `test/agentguard-test` does not detect this. Before
  pushing, run this from the repo root, where `$A` is a cgraf78/actions
  checkout at the SHA in `.github/cgraf78-actions.lock`:
  `bash "$A/.github/actions/shellcheck-inventory/run.sh" "$PWD" .github/shellcheck-files.txt`.
- A second inventory, `runtime_shell_files` in `test/agentguard-test`,
  must list exactly the shell files under `bin lib share support`. New
  runtime files go in both; test and example files go in the
  `.github` inventory only.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`. Edit `scripts/checkout-installer.conf`,
  then run `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at
  the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't
  rename it.
